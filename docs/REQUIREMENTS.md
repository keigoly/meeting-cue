## 0. 要旨

会議・講演・オンライン会議の音声を **手元の Mac でリアルタイムに文字起こし**し、相手の発言が「自分への質問」だと **Jev(判定専用モデル)が数百 ms で判定**したら、**Obsidian Vault の知識**と**質問者の意図の読み**を添えて、**回答候補**と**こちらから返すべき逆質問の候補**を画面に即座に出す道具。自分が登壇者として質問を受ける側でも、参加者として登壇者に質問する側でも使う。

Meeting Cue! は録音して後で読む道具ではなく、「**聞きながらその場で出す**」道具。ローカル処理・mic/speaker の 2 チャネル・jq で扱える JSON・薄い UI を大事にする。

順番は **Mac → Windows → GitHub 公開**。公開リポジトリのコミット方針は別途相談(未着手)。

## 1. 背景と目的

| 項目 | 内容 |
|---|---|
| 困りごと | 会議中に質問されたとき、手元の資料や過去の知見(Vault に溜めたもの)を思い出して言葉にするまでに時間がかかる。講演を聴くとき、良い質問を組み立てる余裕がない。 |
| 目的 | 「質問の終わり → 最初のキュー表示」を **2.5 秒以内**にし、会話の流れを止めずに補助を受ける。 |
| 前提資産 | 作者の別プロジェクト(Zoom の同時翻訳)で **SpeechAnalyzer(macOS 26 内蔵・オンデバイス)の日本語ストリーミング STT・Core Audio process tap(相手側音声の取得)・最前面 NSPanel 字幕・ポーズ検出セグメンター**が実測済み(partial 追従 p50 59ms・1 時間連続で劣化 2.7%)。**コードは import せず、同じプロトコルの写しを本リポジトリに置く**。 |

## 2. 用語

| 用語 | 意味 |
|---|---|
| セッション | 1 回の会議・講演。開始〜終了で 1 ディレクトリの記録になる |
| チャネル | 音声の出所。`mic` = 自分(手元マイク)/ `system` = 相手(オンライン会議アプリの出力音声)/ `room` = 対面会議でマイクに入る全員 |
| 発話 | セグメンターが確定した 1 まとまりの文字列 |
| 判定 | Jev に発話を渡して得る型付きの答え(質問か・自分宛か・意図・分野・緊急度・回答長・知識要否) |
| キュー(cue) | 画面に出す補助カード。3 種: **回答候補** / **逆質問候補** / **ナレッジカード**(Vault の該当箇所) |
| モード | 自分の立場。`participant`(会議参加者)/ `presenter`(登壇者)/ `audience`(聴講者)。キューの重み付けと文面が変わる |
| 機微モード | クラウド送信を止める運用(`privacy = "local"`)。文字起こしと Vault 検索はローカルで動き続ける |

## 4. 機能要件

### FR-1 音声取得(2 チャネル)
- `mic`: 既定の音声入力(AirPods 等)を AVAudioEngine で常時取得。
- `system`: オンライン会議アプリの出力音声を **Core Audio process tap**(macOS 14.4+)で取得。対象はアプリ名の部分一致(`zoom` / `teams` / `chrome` 等)か PID。「システム全体タップ(自分のプロセス除外)」も選べる(Zoom の描画プロセスが版で変わる問題への対策・前例あり)。
- BlackHole 等の仮想デバイスは**使わない**(設定が増えるため)。
- チャネルごとに別プロセス(Swift ヘルパー)で動かし、片方が落ちても他方は続く。

### FR-2 リアルタイム文字起こし(オンデバイス)
- macOS 26 **SpeechAnalyzer / SpeechTranscriber**(`ja-JP` 主・`en-US` 可)。音声はクラウドへ送らない。
- 部分認識(partial)を 400 ms 以内で追従し、確定(final)を出す。日本語は自動 final が出ないため、セグメンターの `finalize(through:)` で確定させる(前例の知見)。
- Swift ヘルパーの stdout は **1 行 1 JSON**(`ready` / `partial` / `final` / `bye`)。stdin は `finalize` / `quit`。Python 側はこのプロトコルだけを知る(Windows 版は同じプロトコルの別実装)。`start_s` はその文の**話し始め**(2026-09-27: 最初の語の時刻。結果の範囲は前の確定の終わりから始まり、間の無音を含むことがあるため。語の時刻が無ければ範囲の始まり)。Windows 版も話し始めを入れる。セグメンターが長さで切った final の切れ端を繰り越すときは、切り出した final の範囲と位置から始まりを見積もる(以前は最後の partial の範囲を使い、長い無音の後の質問が最大 60 s 早く記録されていた)。

### FR-3 発話の確定(セグメンター)
- ポーズ検出(partial 更新が止まってからの経過 ms)と、末尾の形(文末・助詞・語中)で確定タイミングを変える。**音源で cadence が違う**: マイクは partial が数十 ms 間隔、会議アプリの出力(tap)とファイルは約 1 秒周期のバースト(実測ギャップ p50 976 ms / max 1,000 ms)。既定はマイク 500 / 900 / 300 ms、tap 1,200 / 1,600 / 1,100 ms(`[segmenter]` / `[segmenter_tap]`)。**自分の声(channel=mic)は tap と同じ長さ**(`[segmenter_self]`・2026-09-27 keigoly様 選択: 短く切ると文の途中で切れて文脈を失う。読み上げ 91 s を 6 回ずつ再現して CER 平均 28.6% → 26.4%・固有名詞以外 14.9% → 13.2%(揺れも 12.2〜16.3% → 12.6〜13.6% に縮む)。残る誤りは固有名詞(区切り方では直らない)。自分の発言は判定に使わないので確定の遅れは表示だけ)。対面の相手(room)はマイク用の短い値のまま。
- STT は節の途中にも句点を打つ(実測「…の文化。」「…シームと。」)ので、**句点だけで速く切らない**。「用言・丁寧形で終わり、かつ句点付き」のときだけ速い経路にする。
- 相づち(はい / ええ / うん / なるほど)は捨てる。
- 文末記号で分割し、未完結の切れ端は次の発話に繰り越す。
- **間が来ないまま話し続ける音声も切る**(2026-09-26 追加): 発話が `long_utterance_ms`(既定 8 s)を超えて partial に文末があれば、間を待たずに finalize する。`long_utterance_hard_ms`(既定 20 s)を超えたら文末がなくても切る。文末より後ろの言いかけは次の発話へ繰り越す。実測: 一人語り 5 分で 1 回の確定が抱える音声が p50 21.5 s / max 37 s → 9.2 s / 19.9 s(実再生の tap では max 59 s だった)。0 で無効。

### FR-4 判定層(Jev)
- 発話(`system` / `room` チャネルのもの)が確定するたび、Jev に **1 パスで固定の質問群**を投げる(§8)。目標 ≤ 500 ms(Air からの実測 272 ms)。
- 判定の使い道: (a) 質問かつ自分宛なら**キュー生成を起動**、(b) 質問でなくても分野が変わったら**ナレッジカードだけ**出す(LLM を呼ばない・安い)、(c) 緊急度と回答長で表示の優先度と文量を変える、(d) 意図をキュー生成のプロンプトに渡す。
- Jev に渡す state は「当該発話 + 直前 2 発話 + モード + チャネル」だけ(≤ 1,500 字)。会議全文や Vault 本文は渡さない。
- Jev が取れない(未設定・タイムアウト・非 200)ときは**ヒューリスティック判定**(疑問符・「〜ですか / でしょうか / 教えて / どう」等の末尾パターン)に落とし、判定なしでも動く。
- **全判定を記録**する(発話 id・答え・確率・所要 ms)。日本語での Jev の精度は公式に未検証(CJK)なので、記録から較正する(shadow mode の流儀)。

### FR-5 ナレッジ検索(Vault のローカル索引)
- Obsidian Vault を **SQLite FTS5(trigram トークナイザ)** で索引化。形態素解析器なしで日本語が引ける。目標 ≤ 50 ms / 検索。
- チャンクは見出し単位(上限 800 字)。ノートのパス・見出し・更新日を持つ。
- 索引対象は設定で決める(既定: `01_Projects` / `02_Ideas` / `03_Resources` / `04_Context`。除外: `Session_Log` / `Discord_Log` / `Compact_Snapshots` / `Memo_Private` / `00_Inbox/_processed` / `_Archive` / **`03_Resources/YouTube`**。開発環境の運用ログと仕事のフォルダは個人の設定で足す)。YouTube(1,877 本・203 MB)は実測で索引 1.24 GB・構築 9.3 分・コメント単位の雑音が上位に来たため**既定除外**(**§12 Q5**)。除外時は 1,183 ファイル / 14,977 チャンク / 構築 13.5 s / 検索 p50 0.7 ms。
- 更新は mtime 差分で増分。初回の全量構築は `meetcue index` で明示的に行う。
- 検索語は Jev の分野判定 + 発話中の名詞句(簡易抽出)+ 直前の話題語。埋め込み検索(多言語 e5 等)は Phase 2 の候補で、初版は FTS5 だけ。

### FR-6 キュー生成(LLM)
- 入力: 発話・直前の文脈(最大 10 発話)・判定(意図・分野・回答長)・Vault の該当チャンク(上位 5 件)・モード・自分のプロフィール要約(Vault `04_Context/Professional_Identity.md` の骨子・固定)。
- 出力(構造化 JSON): **回答候補 3 件**(1 行の見出し + 2〜3 行の骨子 + 根拠ノート)・**逆質問候補 3 件**(なぜ聞くのかを 1 行添える)・**意図の読み**(1 行)。
- 先頭の候補から**ストリーミングで表示**(初トークン ≤ 1.2 s)。
- LLM の行き先(既定 → 代替): **OpenRouter 経由 Claude Sonnet 5**(既存の `OPENROUTER_API_KEY`・応答の `usage.cost` を自前台帳へ)→ 高速枠 Claude Haiku 4.5 → 機微モードではローカル MLX(Qwen3-4B-Instruct-2507 4bit・導入済み)か生成停止(ナレッジカードのみ)。行き先は設定 1 行で切り替える。**`provider.order = ["Anthropic"]` を必ず付ける**(実測: 自動配信の AWS 経由は初トークン 3.3 s、Anthropic 直は 1.2 s・Haiku 0.96 s)。
- OpenRouter の運用規約: `provider.data_collection = "deny"`・中国企業運営の配信事業者を既定除外・reasoning 無効。
- 同じ発話に対する二重生成はしない(発話 id で冪等)。生成中に次の質問が来たら**新しい方を優先**し、古い生成は打ち切る。

### FR-6b 選ぶ係(Jev セレクター)
- 出典: Vault `03_Resources/YouTube/AI/2026-09-25_しゃべらない最新AI「Jev」はガチの議論に使えることが分かった.md`(海外Yパパさん)。同じ Claude が書いた候補 5 本から「どれを出すか」だけを Jev に選ばせると、Claude 自身に選ばせるより 27 勝 13 敗(40 戦)。理由は**基準ごとの点数の足し算**で選ぶためブレず、書き手自身の好みに引っ張られないこと。1 回 0.7 秒・0.03 円。**どの場面でどの基準を重く見るかは人が決める**。
- 適用: 候補を多めに生成(既定 回答 5・逆質問 5)し、**各候補を Jev が基準別に採点**(score 型)→ モードと意図に応じた重みで合計 → 上位 3 件に ★ を付けて並べ替える。ストリーミング表示は残し、行が完成した候補から順に採点を並行して走らせる(最初のキューが出る速さは変わらない・並べ替えは生成完了直後)。
- 回答候補の物差し: 正面から答えているか / 根拠の具体性 / その場で口に出せるか / 断定しすぎ・誤りの恐れの低さ / 説得力。逆質問候補の物差し: 相手の意図・前提を引き出すか / 相手がすぐ答えられるか / 次の一手に進めるか / 場に合うか。
- 重み: 既定 + `mode`(登壇者は説得力と安全側・聴講は「引き出す」)+ `intent`(risk は安全と根拠・cost は根拠・clarify は正面から)の上書き。設定 `[selector.weights]` で人が変える。
- 採点が取れない候補(不通・タイムアウト)は末尾に回して表示は続ける(fail-open)。費用は候補 10 本で約 $0.0005。
- 回答 5 本と逆質問 5 本は**別リクエストで並行生成**する(1 本にすると 10〜12 s かかり次の質問で打ち切られる実測。並行で 7 s)。次の質問で打ち切られたときは採点済みの候補だけで途中順位を出す。

### FR-6c 質問タブ(こちらから聞くべき質問の先回り)
- 2026-09-26 追加(keigoly様 要望)。相手の質問を待たずに、会話の中身から「今こちらから聞くべき質問」を出し続ける。録音しながら質問を考えるための道具。
- 考え手: **Sonnet 5 が自動**(話が進んだとき・最大 1 分に 1 回)+ **「深く考える」ボタンで Opus 5.5**。「今の話で質問を考える」ボタン(Sonnet)で手動でも出せる。候補は Jev の選ぶ係(FR-6b の逆質問の物差し)で並べ替える。
- 入力: 直近の文字起こし(相手・自分の両方)・モード・プロフィール・Vault の該当チャンク。出力: 質問 3〜5 件(ねらい 1 行・聞くとよい頃合い)。
- **優先順位(最重要)**: 相手からの質問の判定(Jev・FR-4)と回答の生成(FR-6)が常に先。Jev が起動を判定したら、質問タブの生成は即座に打ち切り、回答の生成が終わるまで(+ 10 s)再開しない。質問タブの生成は判定の待ち行列を通らない別タスクで走らせ、判定を遅らせない。回答の e2e(§5.1)を悪化させないことを受け入れ基準にする。
- 2026-09-26 実装(U3 + U4): 自動は「前回から 60 s 以上・会話が 120 字以上進んだ・回答中でない・回答後 10 s 経過・一時停止中でない」とき。手動(今の話で質問を考える = Sonnet / 深く考える = Opus 5.5)は一時停止中も効き、回答中に押したら回答の後で実行。記録は cues.jsonl の `kind=plan` と metrics の `plan_start / plan / plan_select / plan_preempt`。設定は `[planner]`。「深く考える」の Opus 5.5 は OpenRouter で思考を切れない(400「Reasoning is mandatory」)ため `reasoning.effort=medium`・上限 4,000 トークンで呼ぶ(初出力まで約 9 s・1 回約 $0.03)。受け入れ(iroots 17 問・質問タブ自動のまま): 取りこぼし 0/17・誤起動 1/19・最初のキュー p50 2.63 s / p90 3.00 s(基準 2.44〜2.62 s / 2.92〜3.25 s)。質問タブは 7 回中 4 回が相手の質問で中断(優先制御が働いた)。

### FR-7 表示
- 最終形(2026-09-26 改訂): **通常のウィンドウ 1 枚**(サイドバー + 本文)。録音中は既定で「常に手前」(全画面の Zoom の上にも出る・切替可)。旧来の半透明パネル(`meetcue run --ui overlay`)はこのウィンドウの動作確認が済むまで残す。
  - **サイドバー**: 録音中のカード(題名・経過時間・**マイクとスピーカーの波形**)、過去のセッション一覧(「今日」「これより前」・題名・長さ・日時)。一覧の記録を**右クリック**すると「録音を書き出す… / Google Drive に移動… / 削除」(2026-09-26 keigoly様。中身は FR-9)。Google Drive にある記録は雲の印付きで一覧に出る。
  - **録音中の本文**: 題名(クリックでその場で編集・2026-09-26 に鉛筆のボタンを廃止)・「日時・録音中・この Mac」・右上に「録音を停止」。タブ **文字起こし**(相手と自分の発言がリアルタイムで流れる。**新しい発言を上に足し、古いものは下へ流れる**(2026-09-28 keigoly様「下に追加されるのではなく、上から次々と追加して下に流れていく」)。途中の文字の 1 行も一番上。上端にいれば上端に留まり、下の古い発言を読んでいる間は位置を動かさない。録音後の画面は古い順のまま = 回答タブと同じ)/ **質問**(FR-6c)/ **回答**(相手からの質問への回答候補・逆質問・ナレッジ。FR-6 / FR-6b)。タブは**利用者が切り替える**(2026-09-26 keigoly様: 相手の質問を検知しても回答タブへ自動で移らず、回答タブに件数の印を付ける)。録音の開始画面の題名は Enter では始まらない(Enter は日本語の確定だけ・「開始」ボタンで始める)。「録音を開始」の右に ▾ を付け、**クイック録音を開始**(会議に参加・題名なし)/ クイック録音を開始(仕事の会議・LOCAL)で開始画面を出さずにすぐ始める(2026-09-27 keigoly様: メニューバーと同じくウィンドウからもすぐ始めたい)。録音中・保存中は ▾ を出さない。録音中の途中の文字の 1 行も、1 文字なら出さず 6 s 更新も確定もなければ消す(ライブ字幕と同じ。無音の間の「あ」が録音の終わりまで残っていた)。

  - **開発者向けの切り替え(既定オフ・自己責任)**: `config.toml` の `[llm] subscription_cli = true` にした開発者だけ、接続先に「Claude サブスク(Claude Code 経由)」が出る。アプリは**本人の Mac でログイン済みの Claude Code(`claude -p`)を呼ぶだけ**で、認証情報には触れない(集めない・保存しない・中継しない)。`--safe-mode`(CLAUDE.md・フック・MCP・プラグインを読まない)・`--tools ""`・`--no-session-persistence`・専用の作業フォルダで動かし、個人の文脈を混ぜない。LOCAL では使わない。料金は API の台帳に数えない(プランの利用枠を使う)。
  - **速さ**(2026-09-26 実測・Sonnet 5): 毎回起動すると準備 3.7〜4.2 s・初トークン 4.5〜5.2 s でリアルタイムに向かない。起動を先に済ませて待たせた(温めた)プロセスなら送ってから初トークン 0.8〜1.7 s(OpenRouter 1.2〜1.6 s と同等)→ 録音中は回答・質問タブ用に温めたプロセスを 2 つ持ち、1 つの依頼ごとに使い捨てて入れ替える(会話を溜めない)。深く考える(Opus)とサマリ(Haiku)は待てるので都度起動。
  - keigoly様 の開発環境はこの切り替えをオンにして使う。OpenAI(Codex CLI)の同じ仕組みは必要になったら足す。
- **API キーの保管**: Mac は **キーチェーン**(サービス名 `local.meetcue`・アカウント = 接続先)。書き込みは `security -i` に標準入力で渡す(コマンドラインにキーを出さない)。読む順はキーチェーン → 環境変数 → `~/.secrets/meeting-cue.env`(既存の設定はそのまま使え、ファイルは書き換えない)。画面へはキーを返さない(設定済みか・どこにあるかだけ)。「確認」は各社の無料の認証確認(モデル一覧・キー情報)だけを呼ぶ。Windows の保管方法は別途決める。
- **オン/オフ**(`ui.json`・既定はすべてオン): 「回答候補・質問タブ・サマリを AI で作る」(生成)/「質問を判定する(Jev)」(**オフなら質問の検出もしない** = 回答タブは動かず、選ぶ係の ★ も付かない)/「Google Drive へ移動を使う」。生成と Jev を両方オフにすると**録音だけ**(文字起こしと録音は Mac の中だけで、外へは何も送らない)。Jev は OpenRouter 経由なので、オンにするには OpenRouter のキーが要る。LOCAL は従来どおり優先(クラウド呼び出しなし)。

- **初回の案内**: はじめて起動したとき(キーも設定も無いとき)に案内を出す: 使い方(AI で支援 / 録音だけ)→ 接続先とキー → Jev → Google Drive → 完了。⚙ からもう一度開ける。既にキーがある環境では出さない。

### FR-11 機微モード(仕事の会議)
- `privacy = "local"` で **クラウド呼び出しを全て止める**(Jev → ヒューリスティック、LLM → ローカルか停止)。STT と Vault 検索はもともとローカル。
- セッション記録は常に `~/.meeting-cue/`(非 git・Vault などに本文を出さない)。LOCAL の記録は Google Drive へ移せない(画面で押せないうえ、サーバも断る)。書き出しは手元のフォルダへのコピーなので可(置き場所は利用者の判断)。
- 起動時と画面に「LOCAL」バッジを出し、送信していないことを見て分かるようにする(沈黙を成功と読ませない)。

### FR-12 Windows 対応(第 2 段階)
- 差し替える 3 点: 音声取得(WASAPI loopback + mic)・STT・最前面ウィンドウ(pywebview + WebView2)。ホットキーは `pynput`。
- Python 本体(セグメンター・判定・検索・生成・Web UI・記録)は共通。STT ヘルパーのプロトコル(FR-2)を守れば差し替えだけで成立する。
- **STT は faster-whisper の large-v3-turbo(CUDA・float16)+ Silero VAD(faster-whisper に同梱の `silero_vad_v6.onnx`)に決定**(2026-09-27 keigoly様。比較は `spikes/WINDOWS_STT.md`: CER 1.1 %・final は話し終わりから p50 0.73 s / p90 0.90 s・句読点付き・VRAM 1 チャネル 2.4 GB)。partial は区間の頭から 0.3 s ごとに認識し直し、文字が変わったら出す。final は VAD が区間を閉じたとき(無音 0.3 s)か stdin の `finalize`。区間は最長 20 s で切る。`start_s` は VAD の区間の始まり。
- **音声認識のパッケージは STT ヘルパー専用の仮想環境にだけ入れる**(2026-09-27 keigoly様)。本体は標準ライブラリのまま。ヘルパーは `helpers/windows/stt_helper/stt_helper.py`(専用環境の python で動く・本体を import しない)。環境は `~/.meeting-cue/stt-venv`、モデルは `~/.meeting-cue/models/`(どちらも `packaging/windows/setup.ps1` が作る)。
- NVIDIA の GPU が要る(CPU では 1 回の認識に 8.7 s かかり実時間に届かない)。GPU の無い PC への縮退(Windows 内蔵の SAPI・sherpa-onnx の ReazonSpeech)は公開後に決める。
- 会議中はネットへ出ない: ヘルパーは `HF_HUB_OFFLINE=1` で動き、モデルはセットアップのときだけ取る(LOCAL の約束)。
- **ウィンドウは pywebview(WebView2)**(2026-09-27 keigoly様)。Mac の overlay_helper と同じく別プロセスのヘルパー(`helpers/windows/window_helper/`)で、pywebview はアプリ用の仮想環境 `~/.meeting-cue/app-venv` にだけ入れる(本体は標準ライブラリのまま・同じ環境の python で動かすが import しない)。画面の HTML は変えない: ヘルパーが `window.webkit.messageHandlers.meetcue.postMessage` を pywebview の API へつなぐ写しを差し込み、同じ `cmd`(top / pin / drag / main / theme)を受ける。ライブ字幕は画面の右上の「ライブ字幕」ボタンから開く(ホストが `window.meetcueHost = {caption: true}` で名乗ったときだけ画面が出す・Mac はメニューバー)。2026-09-28: ウィンドウの白いメニューをやめ、アイコン(AppUserModelID + WM_SETICON)とタイトルバーのダーク / ライト(DWM)を画面の外観に合わせた(keigoly様)。同日、スタートメニューのショートカットにもウィンドウと同じ AppUserModelID(`keigoly.MeetingCue`)を書く(`setup.ps1` → `window_helper.py --stamp-shortcut`)。無いと、動いているウィンドウのピン留めが引数なしの python.exe を指し、以後のウィンドウがタスクバーで Python のアイコンにまとめられた(keigoly様「再起動しても Python のアイコンが残る」)。
- **API キーは Windows の資格情報マネージャー**に保存する(2026-09-27 keigoly様・Mac のキーチェーンに当たる)。ctypes で advapi32 の CredWrite / CredRead / CredDelete を呼ぶ(依存なし)。名前は `local.meetcue/<接続先>`。キーを画面・ログ・コマンドラインに出さない。
- **Windows の初版の範囲**(2026-09-27 keigoly様「最小で公開」): `setup.ps1` でスタートメニューに登録 → ウィンドウで録音・ライブ字幕・記録・設定・書き出し(音声を重ねるのは PyAV)が使える・「常に手前」。**次の版に回すもの**: タスクトレイ常駐・グローバルホットキー・自動更新・字幕の固定(クリックを下へ通す)・Google Drive への移動。README に明記する。

## 5. 非機能要件

### 5.1 レイテンシ予算(質問の終わり → 最初のキュー表示)

| フェーズ | 目標 | 根拠 |
|---|---|---|
| STT partial 追従 | ≤ 100 ms | 前例の実測 p50 59 ms(マイク)/ ≈ 0 ms(tap) |
| 発話確定(ポーズ) | 300〜900 ms | セグメンターのしきい値(末尾の形で可変) |
| Jev 判定 | ≤ 500 ms | 実測 272 ms(Air → OpenRouter) |
| Vault 検索 | ≤ 50 ms | FTS5 |
| LLM 初トークン | ≤ 1.2 s | OpenRouter 経由 Claude(Phase 0 で実測) |
| **合計 p50** | **≤ 2.5 s** | 2026-09-25 合成会議で **2.33 s**(3 質問) |
| **合計 p90** | **≤ 4.0 s** | 同 2.87 s |

- ナレッジカードだけ(LLM なし)は ≤ 1.5 s。

### 5.2 費用
- 1 時間の会議で **$0.50 前後**(Jev ≈ 1,000 判定 × $0.00005 = $0.05・生成 30 質問 × 約 $0.017(回答・逆質問の 2 本)+ 採点 $0.0005 ≈ $0.53。`--fast`(Haiku)なら約 $0.25)。
- 質問タブ(FR-6c)を足すと 1 時間あたり約 $1 増える見込み(Sonnet の自動生成 最大 60 回 × 約 $0.015)。Opus の「深く考える」は 1 回あたり数倍。運用で月上限の見直しが要る(実測してから決める)。
- 自前台帳(`~/.meeting-cue/ledger.json`)に `usage.cost` を積み、**月上限(既定 $10)で fail-closed**(超えたらナレッジカードのみで続行し、画面に出す)。

### 5.3 プライバシーと境界
- 音声はクラウドへ送らない(STT はオンデバイス固定)。クラウドへ出るのは発話テキスト・直前文脈・Vault の該当チャンクだけ。

### 5.4 可用性と縮退
- クラウド不通・鍵なし・台帳超過でも **文字起こし + ナレッジカード**は動く(段階的縮退)。落ちたときは画面に理由を出す。
- Swift ヘルパーが死んだら自動再起動(最大 3 回)し、記録に残す。
- 会議アプリの退出で自動停止(Zoom の CptHost 検知の前例)。初版は手動停止。

### 5.5 資源・熱
- M5 MacBook Air(24 GB・ファンレス)で 1 時間連続運転して遅延劣化 5% 以内(前例 2.7%)。
- 常駐メモリ: ローカル LLM を使わない構成で 1 GB 未満。機微モードでローカル LLM を載せると +2.3 GB(Qwen3-4B 4bit)。

### 5.6 可観測性(user CLAUDE.md Step 1)
- 全フェーズが `rid`(発話 id)・`phase`・`ms`・`ok`・`error` を JSONL に出す。`meetcue report <session>` で p50/p90 と失敗数を集計する。

## 6. システム構成

```
[自分の声]               [相手の声(Zoom/Teams/Meet)]           [会場の声(対面)]
   │ 既定の入力                │ process tap                           │ 既定の入力
   ▼                          ▼                                       ▼
┌─ Swift ヘルパー(macOS)───────────────────────────────────────────────────────┐
│  stt-helper (mic, ja-JP)        tap-helper (system, ja-JP/en-US)            │
│  SpeechAnalyzer → JSONL(partial/final) を stdout へ / stdin: finalize・quit │
└──────────────┬────────────────────────────┬──────────────────────────────────┘
               ▼                            ▼
┌─ Python オーケストレーター(meetcue)──────────────────────────────────────────┐
│  stt_reader → segmenter(ポーズ検出・相づち除去・文分割)                          │
│     ├─ judge: Jev(OpenRouter decisions) / heuristic(機微モード・失敗時)        │
│     ├─ knowledge: Vault FTS5 索引(~/.meeting-cue/index/vault.sqlite)         │
│     ├─ cues: LLM ストリーミング(OpenRouter Claude / ローカル MLX)              │
│     ├─ session: transcript / judgments / cues / metrics(JSONL)              │
│     └─ ui: terminal(Phase 1)→ FastAPI + WebSocket(Phase 3)                  │
└──────────────┬───────────────────────────────────────────────────────────────┘
               ▼
┌─ 表示 ───────────────────────────────────────────────────────────────────────┐
│  Phase 1: ターミナル  /  Phase 3: 最前面パネル(pywebview or NSPanel+WKWebView) │
│  ホットキー helper(Carbon)                                                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 処理フロー(1 発話)

1. `final` 到着 → セグメンターが発話を確定(`rid` 採番・`segment` を記録)。
2. `mic` チャネルは記録だけ(自分の発言は判定しない)。`system` / `room` は 3 へ。
3. Jev 判定(≤ 500 ms・並行して Vault 検索を先行実行)。
4. `question ∧ addressed_to_me` の確率が閾値以上 → キュー生成(ストリーミング)。閾値未満で分野が変わった → ナレッジカードのみ。
5. 表示更新・記録。生成中に次の質問が来たら古い生成を打ち切る。

## 7. 技術選定

| 層 | 選定 | 状態 | 理由 / 代替 |
|---|---|---|---|
| 本体言語 | Python 3.12(uv・`pyproject.toml`) | 確定 | 前例と同じ。Windows へそのまま持ち込める。代替: Swift 単体(Mac 専用になる) |

| 配布(Windows) | clone / ZIP + `packaging\windows\setup.ps1`(専用環境とモデルを手元で用意) | 確定(2026-09-27 keigoly様・FR-13) | インストーラと Releases は署名と容量の問題で当面なし |
| ウィンドウ(Windows) | pywebview(WebView2)の別プロセスのヘルパー。アプリ用の仮想環境 `~/.meeting-cue/app-venv` にだけ入れる | 確定(2026-09-27 keigoly様) | 代替: Edge のアプリ表示(依存なしだが「常に手前」が作れない) |
| API キーの保管(Windows) | 資格情報マネージャー(ctypes で advapi32) | 確定(2026-09-27 keigoly様) | 依存なし。代替: DPAPI の暗号化ファイル / 手書きの `~/.secrets` |

| 知識検索 | SQLite FTS5 trigram(stdlib のみ) | 確定 | 形態素解析器不要・依存ゼロ。Phase 2 で埋め込み(multilingual-e5-small・MLX/ONNX)を上乗せ |
| キュー生成 | 接続先を設定で選ぶ(FR-10b): OpenRouter 経由 Claude(既定・Sonnet 5 / Haiku 4.5 / Opus 5.5)/ **Anthropic 直**(`claude-sonnet-5` / `claude-haiku-4-5` / `claude-opus-5-5`)/ **OpenAI 直**(モデルは利用者がキーのモデル一覧から選ぶ) | 確定(2026-09-26 第 2 段) | **stdlib の urllib だけ**(公式 SDK は入れない・keigoly様 決定)。各社の公開仕様どおりの HTTP + SSE を小さく写す(`cues/anthropic_direct.py`・`cues/openai_direct.py`)。ローカル MLX は機微モードの候補のまま。Claude Max(CLI)は起動 3〜8 s で不向き |

| ホットキー | Carbon `RegisterEventHotKey`(Mac)/ `pynput`(Windows) | 確定 | アクセシビリティ許可不要(前例) |
| 記録 | JSONL(segment のキー: channel / text / start_seconds / end_seconds) | 確定 | jq で扱える |

## 8. Jev の質問設計(固定・id は記録のキーになるので変えない)

state(例): `{"mode":"presenter","channel":"room","prev":["…","…"],"utterance":"その仕組みは既存の SIEM と競合しませんか"}`

| id | type | 問い(要旨) | 選択肢 / 段階 |
|---|---|---|---|
| `speech_act` | choice | この発話は何か | `question`(質問)/ `request`(依頼)/ `statement`(説明・主張)/ `agreement`(同意・相づち)/ `smalltalk`(雑談)/ `other` |
| `to_me` | noul | 私(モードの立場の人)に向けられた問いかけ・依頼か | — |
| `intent` | choice | 質問者が本当に知りたいこと | `clarify`(定義・確認)/ `how`(手順)/ `why`(理由・背景)/ `feasibility`(実現性)/ `cost`(費用・工数)/ `compare`(比較・代替)/ `risk`(懸念・リスク)/ `schedule`(時期)/ `opinion`(評価・意見)/ `challenge`(反論・指摘)/ `experience`(事例・経験)/ `other` |
| `needs_knowledge` | noul | 答えるのに私の資料・過去の経験(Vault)が要るか | — |
| `urgency` | score | 今すぐ返答が要る度合い | `low` / `medium` / `high` |
| `answer_length` | choice | 適切な返答の長さ | `short`(1〜2 文)/ `medium`(数文)/ `long`(構造化) |
| `topic` | choice | 分野(設定から生成・任意) | 例: `security_network` / `ai_agents` / `broadcast_tv` / `career` / `personal` / `other` |

- 起動条件(既定): `speech_act=question` の確率 ≥ 0.6 **かつ** `to_me` ≥ 0.6。`request` も同様に扱う。閾値は設定。
- 選ぶ係(FR-6b)の採点質問は `meetcue/judge/selector.py` の `ANSWER_QUESTIONS` / `COUNTER_QUESTIONS`(score 型・3 段階)。1 候補 1 呼び出し・並行。

## 13. 受け入れ基準(Mac 初版 = Phase 1〜3 完了)

1. 合成音声のテスト会議(60 秒・質問 3 件)で、3 件とも検出され、各キューが質問の終わりから **2.5 s 以内**に出る(`meetcue report` の p50)。
2. 実際のオンライン会議で **15 分以上**運転して落ちず、相手の質問に対し回答候補 3 件・逆質問候補 3 件・根拠ノートが表示される。
3. 機微モードで起動したとき、外向きの HTTP が 1 本も出ない(記録の `source` が全て `heuristic` / `local`)。
4. 全フェーズの所要 ms が JSONL に残り、失敗が画面と記録の両方に出る。
5. 秘密・個人パスがコードと既定設定に含まれない(公開前提)。
